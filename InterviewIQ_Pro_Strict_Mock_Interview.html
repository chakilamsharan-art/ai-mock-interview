01 / Personalise your session

Set yourself up to succeed.

Choose a role, interview format and difficulty. Strict mode requests full-screen, blocks common clipboard actions, records focus changes and adds answer-verification probes. Sessions run 20–60 minutes with 6–30 main questions.

Progressive mode increases challenge through the session. Every question is tagged with its level.

Integrity-first interview: paste, drop, copy/cut and common assistance shortcuts are blocked where the browser permits; bulk text insertion, focus changes and full-screen exits are logged. A follow-up challenge can test whether you understand your own answer. AI-authorship limitation: this offline HTML cannot reliably prove that text was AI-generated or detect another device, extensions, or off-screen assistance. The monitor reports observable events—not proof of cheating. Real server-side AI feedback or detector services are not configured in this file.

Built around the InterviewIQ promise

A coaching workflow, not an open-ended chatbot.

The product concept is designed to make practice relevant, feedback understandable, and the next step obvious.

①

Personalise

Choose the role, experience level, interview type and session length. This prototype selects prompts from a local role-aware question bank and can request full-screen lockdown.

②

Practise

Answer one prompt at a time using text. Your draft is saved locally so a refresh does not immediately erase your work.

③

Review

See five rubric dimensions, observable evidence signals, strengths, a concrete improvement tip and an optional follow-up challenge. The current evaluation is heuristic and intentionally transparent.

④

Improve

Finish with a summary report, export it, and return to practise. Completed reports can be reopened or deleted.

▣

Privacy by default

No account or external API is used in this file. Answers and history stay in browser storage until deleted. This is useful for a demo, but not a secure multi-user production store.

⚙

What production needs

A server-side API, actual AI evaluation with schema validation, an independent integrity service, secure authentication, a database, rate limits, logging, quality review and documented retention/deletion controls.

  • Separate question generation from answer evaluation.
  • Keep API keys out of browser code.
  • Monitor latency, failures, model versions and cost.
Prototype boundary: This implementation is a testable front-end MVP. It does not claim to implement the complete backend/AI architecture or validated pilot targets described in the pitch deck.
